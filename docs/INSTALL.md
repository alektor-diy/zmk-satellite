# ZMK Satelliteの導入

作業は **表示器の準備** と **キーボード側でモジュールをONにすること** の2つです。表示器だけを組み立てても、通常のZMKキーボードは必要な状態を送信しないため表示できません。

```text
キーボード ── いつもの接続 ── PC・タブレット
    └── 状態のお知らせ（BLE広告） ── Satellite
```

## 1. 表示器だけを確認する

[READMEの配線表](../README.md#配線)どおりにXIAOとLCDを接続します。電源は3.3Vです。XIAOへ `firmware/satellite-display.uf2` を書き込み、新しい画面レイアウト・模擬の76%／65%を確認してください。この値はまだキーボードから受信したものではありません。

白画面・欠け・色違いは [画面の切り分け手順](HARDWARE.md) を使います。LCDがない場合は次へ進み、`satellite-ble.uf2` のUSBログで受信だけを確認できます。

## 2. キーボードへ追加する

**普段キーマップを編集する、自分のZMK設定リポジトリ**を開きます。Satellite本体の設定ファイルではありません。

```text
自分のzmk-config/
├─ build.yaml          ← board・shieldはいつもの指定を維持
└─ config/
   ├─ west.yml         ← モジュールを1つ追加
   ├─ keyboard.conf    ← ON設定を1行追加
   └─ keyboard.keymap  ← 今回は変更不要
```

`keyboard` は自分の機種名に読み替えてください。例えばiOraの共通設定は `config/iora.conf` です。自分の設定からまだFWを作れない場合は、先に販売元・設計者から通常のビルド手順を確認します。既存のUF2に設定だけ後付けする機能ではありません。

まず、現在動くFWと設定を保存しておきます。そのうえで `config/west.yml` の `manifest.projects` へ次を追加します。既存のZMK版、fork、他のモジュールは残し、同じ深さの項目に空白を揃えます。

```yaml
    - name: zmk-satellite
      url: https://github.com/alektor-diy/zmk-satellite
      revision: main
      path: modules/zmk-satellite
      import: module/west.yml
```

次に、キーボードの適用される共通 `.conf` へ1行追加します。

```conf
CONFIG_ZMK_SATELLITE=y
```

**通常はここまでがキーボード側の設定です。** 左右分割でも共通ファイルへ追加でき、中央側だけが送信します。`_left` / `_right` 等の名前から中央側の物理位置を判定し、残量取得もまとめて設定します。共通 `.conf` を左右別に分割したり、キーボードのCコードを書き換えたりする必要はありません。

追加モジュールや設定の詳細、任意の広告間隔、特殊な分割構成は [キーボード用モジュールの説明](../module/README.md) を参照してください。バッテリーのハードウェア測定が未対応の機種には、ONだけでセンサー対応を追加するものではありません。

## 3. いつもの方法でビルド・書き込み

GitHub Actionsなどで再ビルドし、今回の変更が入った実行が成功してから成果物をダウンロード・展開します。左右分割はそれぞれのFWを各側へ書き込みます。board・shieldをSatelliteのものへ変更しないでください。

ローカルビルドなら、manifest更新後に `west update` を実行し、普段のboard・shield・`ZMK_CONFIG` を維持します。キャッシュの影響を避けるには新しいbuild先か `west build -p always` を使います。

**SatelliteのUF2をキーボードへ書かないでください。** キーボードには、その機種用に作ったFWを使います。通常の導入にペアリング消去や `settings_reset` は不要です。書き込み後は、まず通常の文字入力ができることを確認します。

## 4. 受信を確認する

1. 表示器のXIAOへ `satellite-ble.uf2` を書き込みます。
2. 表示器のUSBシリアルを115200bpsで開き、キーボードを起動して操作します。
3. `ID=... L=... R=... layer=... BT=...` が出れば状態を受信できています。`Scanning active` だけでは受信成功ではありません。
4. レイヤー・BTプロファイルを切り替え、ログの変化を確認します。
5. LCDが準備できたら `satellite-status.uf2` へ切り替えます。

キーボードとSatelliteのペアリングは不要です。初回は近くの他の対応キーボードを止めておくと、意図した機種を選びやすくなります。

## 画面の読み方

- 右上はレイヤー番号です。レイヤー名は表示しません。
- BT1〜BT5は、ZMKのプロファイル内部番号0〜4に対応します。
- `Signal lost / stale` は95秒広告が届かない状態。PCへのBT切断を表す `PAIRED / DISCONNECTED` とは別です。
- peripheralの0%は未取得にも使われるため `--` です。片側だけの鮮度は広告から確定できません。

送信間隔を変えていなければ、Prospector標準の連続状態広告です。キーボード側の電池消費は増える可能性があります。利用したい人がONにする追加機能として扱っています。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| ON設定が未定義 | モジュール追加先、`import: module/west.yml`、`west update`、編集したブランチ |
| モジュール取得に失敗 | west.ymlのURL・revision・import指定とネットワーク接続を確認。専用トークンは不要 |
| 設定が反映されない | 読み込んだ `.conf` のパスをログで確認。古いFW・キャッシュ・別のZMK_CONFIGにも注意 |
| 左右が逆 | 特殊なshield名なら任意の中央側指定を確認 |
| バッテリー片側がない | 元の測定、peripheralのBT_BAS、左右の接続を確認 |
| 別キーボードが表示される | 対象を先に起動するか、Satellite側の固定IDを使う |
| 通常の入力もできない | 保存しておいた元のFWへ戻し、ビルドログと設定差分を確認 |

## 現時点の確認範囲

試作版です。共通モジュール経由のiOra／ZMK v0.3の左右ローカルビルド、受信器のビルド、設定切替を確認しています。新しい共通モジュール構成の実機試験・全機種での導入・電池寿命の確認は未実施です。詳細は [検証記録](VALIDATION.md) と [通信仕様](PROTOCOL.md) にあります。


## 画面とキーボード名

現行画面はバッテリー重視です。上段はキーボード名24pxとレイヤー番号24px、中央は左右残量36px、下段は接続先18pxと接続状態12pxです。レイヤー名・修飾キー・LIVE・RSSIは表示しません。外周の左右余白は14pxで揃えています。長いキーボード名は末尾を省略します。

キーボードの名前広告を同じBLEアドレスの状態広告に関連付け、選択済みkeyboard IDに属する名前だけを表示します。初回の名前取得前はKeyboardを表示します。別送の名前を受け取った後、次の状態広告で名前が反映されるため、待機中は反映まで時間がかかる場合があります。長い名前は末尾省略。組込みフォントにない非ASCII文字は?、全角アンダースコアは_へ置換します。

名前を受信器側で固定したい場合のみ、追加設定で `CONFIG_SATELLITE_KEYBOARD_NAME="My keyboard"` を指定できます。通常は設定不要で、キーボード側の変更はありません。

BT1〜BT5は広告に含まれるプロファイル番号です。USBはUSB HID-readyかつBT未接続のときに表示。両方が成立する場合はBTnとBT + USB READYを表示します。Prospector標準広告にはZMKが選択中の送信先そのものは含まれず、両方接続しているときの優先先は判定できません。USB給電だけではUSBに切り替えません。


### レイヤー番号

画面右上にレイヤー番号だけを表示します。00〜09は2桁表記、10以上はそのまま表示します。レイヤー名は標準広告が4バイトに限られるため表示しません。ZMK Studioの名前を置き換える固定対応表もありません。広告形式とキーボード側の設定は変更不要です。

### BTプロファイルの状態

選択中のBTプロファイルは既存広告のconnected／bondedフラグで判定します。CONNECTEDは接続中、PAIRED / DISCONNECTEDはキーボードにペアリング情報があるが未接続、NOT PAIREDはペアリング情報がない状態です。全5プロファイルの一覧を取得する機能ではありません。USB接続時はUSB CONNECTEDを表示します。広告途絶時はSIGNAL LOST / STALEを優先し、最後の値を淡色表示します。
