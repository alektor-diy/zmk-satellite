# キーボードにZMK Satelliteを追加する

キーボード側の作業は、通常 **モジュールの追加とON設定の2か所**です。キーマップや送信処理のCコードを編集する必要はありません。

## 1. 自分のキーボードの `config/west.yml` に追加

既存の `manifest:` → `projects:` に次を追加します。既存のZMK版や他のモジュールは残してください。

```yaml
    - name: zmk-satellite
      url: https://github.com/alektor-diy/zmk-satellite
      revision: main
      path: modules/zmk-satellite
      import: module/west.yml
```

`import: module/west.yml` まで含めて追加します。これにより互換送信に必要なProspector module v2.2.3も自動取得します。Prospectorを別途登録する必要はありません。**受信器用のルート `west.yml` をimportしないでください。** キーボードのZMK／Zephyr版を置き換えるためのmanifestではありません。

## 2. キーボードの共通 `.conf` に追加

```conf
CONFIG_ZMK_SATELLITE=y
```

例えばiOraなら `config/iora.conf`、Corneなら適用されている `config/corne.conf` です。分割機も共通ファイルへ1行追加すれば、中央側だけが送信し、もう片側は送信しません。必要な右／左残量取得も中央側で有効にします。バッテリーのセンサー定義・残量取得がもともと機能していることは前提です。

## 3. いつもの方法でビルドして書き込む

GitHub ActionsなどでFWを作り直して、各側へ対応するFWを書き込みます。左右共通設定を変えたため、初回は両側を更新すると設定を揃えられます。通常の文字入力を確認してからSatelliteで受信を確認してください。SatelliteとのBluetoothペアリングは不要です。

Satellite側の対象選択・表示・受信タイムアウトなどは受信器側で設定します。広告だけを受信する方式なので、Satelliteの操作からキーボードの送信間隔を遠隔変更する機能はありません。

## 任意: 広告間隔を変える

指定しなければ、Prospector標準の **100〜150ms周期の連続状態広告**です。状態データの更新周期（操作中200ms／待機中30秒）と、実際の電波の周期は別です。電池消費の追加を伴う機能として、必要な人がONにする方針です。

必要な場合だけ、ON設定の下へ次を追加できます。

```conf
CONFIG_ZMK_SATELLITE_ADV_INTERVAL_MS=1000
```

この例は独自の非接続状態広告を約1秒周期にします。Bluetooth仕様のランダム遅延が加わります。設定可能範囲は100〜10000msで、100だけは上流の100〜150ms指定をそのまま保ちます。PCへの接続／再接続広告と、分割側を探すときの上流バーストは変更しません。ZMKの既存広告へデータを載せるpiggyback中の周期はZMK側が管理します。

間隔を長くすると表示の追従や発見も遅くなり、短いレイヤー変化を拾えない場合があります。この設定は省電力効果の保証値ではありません。

## 左右の判定

通常の `_left` / `_right` などで終わるshield／board名から中央側の物理位置を自動判定します。iOraの `iora_left` はLEFTです。標準的な左右分割では追加設定は不要です。

特殊な名前で判定できない場合はビルドログへ警告し、上流の設定（既定RIGHT）を維持します。左右が逆になる構成だけ、次のように指定します。

```conf
CONFIG_ZMK_SATELLITE_CENTRAL_SIDE="LEFT"
```

指定値はAUTO／LEFT／RIGHT／AUXです。ドングルcentralや3台以上の構成は、物理配置・peripheral台数・割当が機種固有なので、上流の `PROSPECTOR_EXPECTED_PERIPHERAL_COUNT` 等も実際の構成に合わせてください。キーボード本来のcentralを変更する設定ではありません。

## ONにしても残量が出ない場合

もとのバッテリー測定が未対応、`ZMK_BATTERY_REPORTING=n`、またはperipheralの `BT_BAS=n` を明示している場合、ON設定だけで電池のハードウェア対応までは追加できません。通常のBLEキーボードでは既存のバッテリー報告設定を使います。特別に無効化している場合のみ見直してください。単体機では1個の残量を表示します。

## 非公開で開発している間だけ必要なこと

このリポジトリが非公開の間、別リポジトリのGitHub Actionsが持つ通常の `GITHUB_TOKEN` だけでは取得できません。取得権限のある認証をCIへ渡すか、ローカルでビルドする必要があります。**一般利用者へ公開する段階では、モジュールを取得可能にすることが2ファイルだけで導入できる前提**です。この機能追加でリポジトリの公開範囲は変更しません。

iOraの専用ブランチには非公開依存用の任意Secret対応を用意しています。`ZMK_SATELLITE_READ_TOKEN` にSatelliteリポジトリの読み取り権限だけを持つトークンを設定する方式です。トークンをwest.ymlやソースへ書かないでください。公開取得できる場合にはこのSecretは不要です。

## 実装とライセンス

送信アルゴリズムはProspector標準を利用します。iOra専用のイベント駆動送信や別広告セットは使いません。共通アダプターが中央側の判定、Zephyr 3.5の初期化互換、任意の状態広告周期を扱います。

上流v2.2.3には待機中に名前だけの広告へ置き換わり続ける箇所があるため、名前と状態を交互に更新する小さな補正をしています。これにより状態広告が待機中も戻り、既定95秒の受信タイムアウトと整合します。無線の連続広告方式やパケット形式を変える補正ではありません。

元のソースはビルド時に固定版から読み込み、著作権表示を保持した生成ソースへ最小限の補正を加えてコンパイルします。`module/sender.c` と `module/CMakeLists.txt` がそのアダプターです。Prospector／carrefinho氏・t-ogura氏・貢献者の皆様に感謝します。元のMIT通知はリポジトリの `licenses/Prospector-Module.txt`、全体の通知は `THIRD_PARTY_NOTICES.md` にあります。

ZMK v0.3のiOraでローカルビルドを確認しています。全機種・すべてのZMK forkでの検証や、新しい共通モジュール版の実機試験が済んでいるわけではありません。
